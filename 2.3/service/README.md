# Сервис классификации обращений RUDATA

По тексту обращения и логину клиента сервис определяет три поля из справочника — **интерфейс, продукт
и тематику**, — для каждого даёт оценку уверенности и признак «нужна ручная проверка». Всё работает
на этом компьютере: тексты обращений никуда не передаются.

Три способа работы:
- **REST-сервис** — другие системы отправляют обращение по одному и получают ответ в JSON;
- **пакетная обработка** — CSV-файл с обращениями на входе, таблица с результатами на выходе;
- **уведомления о всплесках** — по классифицированным обращениям за период находит дни, когда по интерфейсу,
  продукту, тематике или их сочетанию пришло нетипично много обращений.

## Состав папки

```
service/
├── install.bat         установка (Windows)
├── run_server.bat      запуск REST-сервиса (Windows)
├── run_batch.bat       пакетная обработка (Windows)
├── run_spikes.bat      уведомления о всплесках (Windows)
├── server.py           REST-сервис
├── batch.py            пакетная обработка
├── spikes.py           уведомления о всплесках
├── classifier.py       классификация: признаки, модели, языковая модель, правила ручной проверки
├── requirements.txt    библиотеки Python с точными версиями
├── models/             обученные модели и настройки
│   ├── classic_model.pkl   TF-IDF, SVD и модели градиентного бустинга
│   ├── llm_params.json     промпт языковой модели, пороги уверенности, состав гибрида
│   └── access.json         справочник «логин → подключённые продукты»
├── examples/           пример CSV-файла и пример запроса
├── input/              сюда класть CSV-файлы для пакетной обработки
└── results/            сюда пишутся результаты пакетной обработки
```

## Режимы

| Режим | Как работает | Что нужно | Качество на тестовой выборке (сентябрь) |
|---|---|---|---|
| `hybrid` (по умолчанию) | интерфейс и продукт — градиентный бустинг, тематика — языковая модель `qwen3:8b` | Ollama, желательно видеокарта NVIDIA от 8 ГБ | все три поля верны у 72,5% обращений; на ручную проверку 28%; среди принятых автоматически полностью верны 98,5% |
| `classic` | только градиентный бустинг | только процессор | все три поля верны у 36%; на ручную проверку 95% — тематика определяется плохо |

Время на одно обращение: `hybrid` — около 3 с на видеокарте (на процессоре в несколько раз дольше),
`classic` — доли секунды.

## Установка

Нужно: Python 3.12 или 3.13, около 10 ГБ на диске; для режима `hybrid` — Ollama.

### Windows

1. Python с python.org — при установке отметить «Add python.exe to PATH».
2. Для режима `hybrid` — Ollama с ollama.com (установщик для Windows). После установки Ollama работает в фоне.
3. Запустить **`install.bat`** — создаст окружение `.venv`, поставит библиотеки и скачает модель `qwen3:8b` (около 5 ГБ).

### macOS

```
cd service
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
brew install libomp
ollama pull qwen3:8b
```

Дальше команды для macOS — те же, что ниже, с `.venv/bin/python` вместо `.venv\Scripts\python`.

## REST-сервис

Запуск: **`run_server.bat`** (или `.venv\Scripts\python server.py`). Сервис работает по адресу
`http://localhost:8000`, остановить — Ctrl+C. Параметры: `--mode classic` — без Ollama, `--port 8001` — другой порт.

| Запрос | Что делает |
|---|---|
| `GET /health` | состояние сервиса: режим и доступна ли Ollama |
| `POST /classify` | классификация, тело запроса — `{"text": "текст обращения", "login": "логин клиента"}` |

Примеры запроса (файл `examples/request.json`):

PowerShell:
```
Invoke-RestMethod -Method Post -Uri http://localhost:8000/classify -ContentType 'application/json; charset=utf-8' -Body ([System.Text.Encoding]::UTF8.GetBytes((Get-Content examples\request.json -Raw -Encoding UTF8)))
```

curl:
```
curl.exe -X POST http://localhost:8000/classify -H "Content-Type: application/json" --data-binary @examples/request.json
```

Python:
```python
import requests
response = requests.post('http://localhost:8000/classify', json={'text': 'Не открывается шаблон RD Score', 'login': 'rd_user_0051'})
print(response.json())
```

### Ответ

Пример (значения для иллюстрации):

```json
{
  "interface": {"value": "EXCEL_TEMPLATE", "confidence": 1.0},
  "product": {"value": "RD_SCORE", "confidence": 1.0, "by_access": true},
  "topic": {"value": "DATA_MISSING", "confidence": 0.9987},
  "manual_review": false,
  "review_reasons": [],
  "mode": "hybrid"
}
```

| Поле | Значение |
|---|---|
| `interface`, `product`, `topic` → `value` | код из справочника (`dictionary.csv`) |
| `confidence` | уверенность от 0 до 1. В режиме `hybrid` для интерфейса и продукта — согласие двух моделей: 1 — бустинг и языковая модель ответили одинаково, 0 — по-разному; для тематики — вероятность ответа языковой модели. В режиме `classic` — вероятность класса по бустингу |
| `product` → `by_access` | `true`, если на выбор продукта повлиял список подключённых продуктов логина |
| `manual_review` | `true` — обращение нужно проверить вручную |
| `review_reasons` | почему: `UNKNOWN` в каком-либо поле, низкая уверенность, поля противоречат друг другу, логин не найден |

Ошибки: `400` — неверный запрос (нет `text` или `login`), `500` — ошибка классификации (например, Ollama остановлена).

## Пакетная обработка

1. Положить CSV-файлы в папку **`input`**. Нужны столбцы `text` (текст обращения) и `client_id` (логин),
   по желанию `appeal_id` и `created_at` (дата и время поступления — нужна для уведомлений о всплесках).
   Подходит CSV, сохранённый из Excel (разделитель `;` или `,`).
   Пример — `examples/appeals_example.csv`.
2. Запустить **`run_batch.bat`**. Конкретный файл: `run_batch.bat examples\appeals_example.csv`, без Ollama: `run_batch.bat --mode classic`.
3. Результаты — в папке **`results`**, файл `<имя>_classified.csv` (разделитель `;`, открывается в Excel).
   Столбцы: поля обращения, `interface`, `product`, `topic` и их уверенность, `product_by_access`,
   `manual_review`, `review_reasons`. Строки записываются по мере обработки: если остановить, готовое сохранится.

## Уведомления о всплесках

Запуск: **`run_spikes.bat`** — берёт все результаты пакетной обработки из папки `results` (в них должен быть
столбец `created_at`). Другой файл: `run_spikes.bat путь\к\файлу.csv` — подойдёт любой CSV со столбцами
`created_at`, `interface`, `product`, `topic`, например размеченные обращения.

Как работает:
- окно — календарный день; день без обращений — ноль;
- норма — среднее число обращений за 28 предыдущих дней того же типа (будни сравниваются с буднями,
  выходные — с выходными), только по прошлому. Первые 28 дней истории — накопление нормы, уведомлений нет;
- всплеск — за день не меньше 10 обращений, хотя бы вдвое больше нормы, и вероятность получить столько
  случайно при обычном уровне меньше 0,01% (распределение Пуассона);
- отслеживаются интерфейс, продукт, тематика и сочетания «интерфейс × тематика», «продукт × тематика».

Результат — список уведомлений на экране и файл `results/spikes.csv`. Пример уведомления:

```
09.09.2026 | interface × topic = API × PERFORMANCE: обращений за день — 50, обычно меньше 1 в день, в 100 раза больше нормы
```

На размеченных данных за май–сентябрь — уведомления в 15 днях, из них 12 явных инцидентов; случайно за этот
период ожидается не больше 2–3 срабатываний. Настройки — в начале файла `spikes.py`.

## Правила

- Значения полей — только из справочника. Конкретный продукт — только из подключённых логину;
  `NO_PRODUCT` доступен всегда, `UNKNOWN` — при двух и более подключённых продуктах.
- Нет уверенности в продукте (ниже порога) — продукт `UNKNOWN`.
- Логин не найден в справочнике доступов — продукт `UNKNOWN` и ручная проверка: права клиента не предполагаются.
- Ручная проверка: `UNKNOWN` в любом поле, уверенность ниже порога поля, противоречие полей
  (например, интерфейс API с конкретным продуктом) или неизвестный логин.

Пороги уверенности подобраны на валидационной выборке (август) и записаны в `models/llm_params.json`.

## Ограничения

- Модели обучены на синтетических данных. На реальном потоке нужно проверить качество и пересмотреть пороги.
- Справочник доступов `models/access.json` собран из учебных данных. В рабочей системе доступы нужно брать
  из системы, где они ведутся, в момент поступления обращения.
- Файл модели загружается только с версиями библиотек из `requirements.txt`.
- Языковая модель почти не отвечает `UNKNOWN`; уверенность — не откалиброванная вероятность, а сигнал для порога.
- Ответы языковой модели на разных компьютерах (видеокарта NVIDIA, Mac) могут немного отличаться в пограничных
  случаях: модель считает с небольшими численными различиями. Такие обращения имеют низкую уверенность
  и уходят на ручную проверку.
- Сервис доступен только с этого компьютера (`localhost`).
